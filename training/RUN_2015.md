# Measured Stage 1 pilot

This workflow trains the prepared 2015 Jacksonville block using the pinned
Skyfall Stage 1 implementation. It uses the [verified input contract](PILOT.md),
copies the scene into a new run directory, and preserves its geographic record.
Training settings are in [train-2015-pilot.json](../configs/train-2015-pilot.json).

## Run and evaluate

From the TerraSplat root with host GPU access:

```bash
python3 scripts/prepare-skyfall-stage1.py
source scripts/stage1-env.sh
python -m pipeline.training --output artifacts/stage1/pilot-new-run
python -m pipeline.evaluation --run artifacts/stage1/pilot-new-run
```

The output directory must be new. Training preflight verifies the original
prepared scene and the exact recorded backend patches. The run copies the
payload and georeference, checks hashes before training and again afterward,
and retains logs and failure reports if execution stops.

The completed run is `artifacts/stage1/pilot-2015-04`: 30,000 iterations,
102,543 splats, 214.9 MiB peak allocated tensor memory, and a held-out May 2
PSNR of 17.57 dB. [The measured result](RESULT_2015.md) records its metrics and
hashes; models, logs and renders stay in ignored `artifacts/`.

## Fixed experiment

- Target: 30,000 iterations, resolution factor 2, SH degree 2.
- Three training acquisitions; May 2 remains the holdout. No holdout renders or
  image losses are used during training or configuration selection.
- Appearance MLP, depth supervision, pseudo-depth and generative refinement
  are disabled. Spherical harmonics use Skyfall's existing PyTorch evaluation
  option (`--convert_SHs_python`).
- Densification starts after iteration 1,000 and ends at 20,000. A growth step
  is skipped if doubling the current count could exceed 200,000 splats. This
  conservative rule can stop growth below the cap; skipped steps are logged.
- Limits: 4.5 GiB peak allocated tensor memory, at least 256 MiB free sampled
  device memory, and a 30-minute total subprocess budget. These limits define
  this laptop experiment, not the full published Skyfall training recipe.

The first subprocess stops at iteration 1,000 and writes a checkpoint. The
second restores it and continues to 30,000 using the same learning-rate and
densification schedules. The recorded patch fixes the legacy PyTorch checkpoint
load and prevents resume from replacing the requested schedules.

Alongside the model/optimizer checkpoint, an owned sidecar preserves absolute
gradient statistics, Python/NumPy/Torch/CUDA RNG state, the remaining camera
stack and opacity-cooldown state. Hashes are checked before resuming these
locally produced checkpoints. This workflow exercises a deliberate process
restart; it does not claim bit-identical continuation or implement a general
job-recovery service.

Measured runs apply the optimizer step before their final checkpoint, check
finite losses and gradients, and log JSON telemetry every 100 iterations.
Allocated/reserved tensor peaks are tracked by PyTorch. Sampled total device
usage also includes driver/context memory and any other GPU processes; it is
not a per-process peak measurement.

## Evaluation and artifacts

After training, the evaluator renders both the initial and final raw PLYs with
the same cameras and resolution. It reports RGB MSE, MAE and PSNR only over valid
mask pixels, plus alpha coverage. PSNR uses unit-range colors and a 1e-12 MSE
floor. Image metrics are appearance checks, not independent height or map
accuracy evidence. Padding is excluded instead of improving the score through
black borders.

Each run contains:

- `training-report.json`: profile, commands, checkpoint/PLY hashes, source
  adapter hash, schedule/restore evidence, elapsed time and memory measurements.
- `metrics.jsonl` and per-phase logs: optimization and resource telemetry.
- `model/point_cloud/iteration_0/point_cloud.ply`: initial model; later iteration
  folders contain trained raw models. Checkpoints and state sidecars stay local.
- `model/georeference.json`: the unchanged model-to-ENU/ECEF placement record.
- `evaluation/evaluation-report.json`: initial/final image metrics and output
  hashes, with a four-view `comparison.png` and individual rendered images.

PLY and checkpoint validation requires matching iteration/point counts and
finite saved attributes/state. The output is a raw trained scene. Fusion of the
3D filter, export/tiling, geographic accuracy checks and Cesium delivery remain
separate steps.

## Numerical-path finding

The first guarded attempts encountered nonfinite rendered pixels on the CUDA
SH color path. The initial forward pass and SSIM kernel at all pilot image
sizes were inspected; using the existing PyTorch SH option
(`convert_sh_python: true`) allowed stable optimization and densification.
Failed attempts and diagnostic logs remain in ignored artifacts. The selected
renderer option was determined from training failures, without inspecting or
fitting the holdout.

A later failure came from upstream `reset_opacity`: inverse sigmoid applied at
an exact probability endpoint stored `+inf`. The measured-run adapter now
rejects NaN immediately after the reset, clamps raw opacity logits to
`[-13.8, 13.8]`, and checks opacity finiteness every 100 iterations. This
clamp keeps the saved checkpoint finite; it is not evidence of calibrated
opacity.

Run history is intentionally retained. `pilot-2015-02` reached 30,000 but failed
final validation with a nonfinite checkpoint tensor (the opacity endpoint) and
its report remains `failed`. `pilot-2015-03` was terminated with the previous
session at iteration 8,300 of 30,000 and was not resumed; its report now says
`interrupted`. `pilot-2015-04` is the completed run.

The evaluator loads raw PLY attributes itself. Skyfall's `load_ply` restores
only `filter_3D` and expects geometry to come from a checkpoint, so rendering a
saved PLY through the upstream loader alone fails.
